口述答题法：输入 — 活动 — 输出

面试官区分「背概念」和「做过项目」的关键，是你的回答里有没有真实项目的痕迹。把每个回答组织成一个小项目故事，三段式：

输入
什么场景、什么任务落到你头上
需求文档 / 接口文档 / 线上告警 / 提测的版本 / 要压测的接口——一句话交代背景，让面试官知道你在什么约束下干活。
活动
你具体做了什么（1~3 个动作）
设计用例、搭框架、抓日志、调参数、推动开发……动作要具体到工具和数字，不要说「我认真做了测试」。
输出
交付了什么、效果如何
缺陷数、用例数、覆盖率、耗时下降、拦截过几次事故、产出过什么文档。最后可以补一句反思或教训，会显得更真实。
✗ 像背的「接口测试是对系统间接口的测试，主要包括参数校验、鉴权验证、异常场景……」
✓ 像做过的「输入——我上个项目是电商下单链路，开发提测后给了我 Swagger 文档和测试环境；活动——我先用 Postman 把 23 个接口跑通冒烟，再用 pytest + requests 补了 180 条自动化，覆盖参数边界、鉴权和幂等；输出——每天定时回归，先后拦截过 3 次金额计算的 bug，提测打回率从 30% 降到 8%。」

默写自测时，每一题的答题框都按这个框架写；写不出来，说明这道题还没真正「做过」，点「答题结束 · 判分」对照参考答案再补。

判分怎么看点「答题结束 · 判分」后先出分数，再给「答到了 / 还缺」两行要点。分数 = 参考答案要点覆盖率（占大头）+ 篇幅够不够口述 45~90 秒 + 有没有分点、数字和项目视角。浅色标签表示「提到了但不完整」。全部在本地算，不联网、不上传；语义准不准最终还得你自己核，想更严就点「导出默写」发给 AI 批。
